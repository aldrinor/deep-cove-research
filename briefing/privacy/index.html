Abstract

Most AI services ask a privacy office to trust a contract about data that sits on someone else's servers, often outside Canada. What a privacy office can verify is custody: who holds the data, on whose hardware, and what crosses the edge. Deep Cove is built around custody: the Core has no internet path, the only outbound crossing is a cleaned search query with no patient identifiers, and Deep Cove Intelligence holds no copy and has no remote access. BC gets a privacy position it can check for itself, a PIA Input Pack ready for its template, and a log that shows every crossing.

1What never happens to patient data

Each statement below is literally true of Deep Cove as delivered to a BC facility. Each one names the mechanism that makes it true and how BC checks it, so none of them rests on our word.

01

Records Kept in the Facility

Patient records never leave the facility.2 The Core has no internet path, and the only outbound crossing in the whole system is a cleaned search query, with the requests for the public pages it returns, carrying no patient identifiers.

How BC checks itEvery outbound query, and every blocked one, is written to the log; BC's privacy officer receives a daily sample and a weekly report.

02

No Training on Patient Records

Patient records are never used to train any model. Deep Cove is delivered with no training system, and Deep Cove Intelligence never receives the records.

How BC checks itThe software inventory shipped with every release, and the model fingerprint checked at every start (section 3).

03

No Vendor Copy, No Remote Access

Deep Cove Intelligence holds no copy of patient data and has no remote access. Our engineers work on site only, escorted, with every entry logged.

How BC checks itThe access log records every entry and every console session; there is no remote path to audit because none is built.

04

No Reporting Home

Nothing reports back to Deep Cove Intelligence. No vendor telemetry, no usage analytics and no licence check leave the facility. Alarms go one way to BC's own security team and carry no patient text.

How BC checks itThe outbound allow-list and the Web Librarian's log show every destination the system can reach.

05

No Action without a Gate Check

The AI never reaches the internet or a database by itself. It can only place fixed-form orders through the Gates, and separate machines check each order before anything is fetched.

How BC checks itThe independent penetration test before go-live covers the Core, the Gates and the update path.

06

Only Records the Clinician May Open

Kit never reads a record the signed-in clinician is not allowed to see. The Records Librarian checks every request against that clinician's own access rights, never a broad service account.

How BC checks itEach record request is logged with the clinician, the purpose and the fields returned.

Each statement is built into the design and written into the agreement. BC can hold Deep Cove Intelligence to both.

2The one line that crosses outward

Kit reads current medical guidance, so one controlled line reaches the internet: the Web Librarian's. It carries short search words out and public pages back; the Web Librarian rebuilds each page as plain text before anything reaches the Core. The line never holds patient data, and the Core never touches the internet.

Identifiers are blocked by mechanism, not by policy. A check inside the Core and a second, independently written check on the Web Librarian refuse any search that contains the patient's name, Personal Health Number, date of birth, address, phone or chart number. The Web Librarian then rebuilds the query from an approved medical vocabulary, so the AI's own words are never sent as written.

Sites that want no outbound line at all choose the Sealed Library. A curated medical library is kept on site and refreshed through the Delivery Bay, so no search words leave the facility.

Expert DetailHow the Outbound Check Works
  • Layer 1, inside the Core. The order check knows the identifiers in the current session, supplied by the Records Librarian and the Front Door. It refuses any search containing them, in exact or normalized form, or any number shaped like an identifier.
  • Layer 2, on the Web Librarian, written separately. Pattern detectors for BC Personal Health Number shapes and other health-card and chart-number shapes, full dates, Canadian postal codes, phone numbers, email and street addresses; person-name detection; a vocabulary allow-list in which every word must belong to an approved medical and general lexicon; numbers only with units (“500 mg”, “38.5 °C”); shape and randomness checks that refuse encoded strings.
  • Rebuild. The outbound query is assembled from the canonical vocabulary forms of the accepted words. The AI's text is never forwarded byte for byte.
  • Rate caps. Per-session and per-site limits on searches per minute and per day keep any hidden channel to a very low, logged rate.
  • No identity on the line. One shared outbound address for the site; no cookies, no accounts and no user identifiers go to any search service. The fetching machine is rebuilt from a clean image every 24 hours.
  • Legal reading. FIPPA defines personal information as “recorded information about an identifiable individual” (Schedule 1). The cleaned query is built to carry none, and BC's privacy office records that determination in its PIA. The cleaned search words are sent to a public search service that may operate outside Canada. Because they are built to carry no personal information, s.33.1 is not engaged; BC's privacy office records that determination in its PIA, and a site that does not accept it chooses the Sealed Library.
  • Sealed Library. A per-site option. The library is assembled from open public sources (for example PubMed and Health Canada's Drug Product Database) plus references BC licenses, and refreshed on sterilized media. With it, the Web Librarian has no internet line.

3Never used for training, and how BC verifies it

A training ban is stronger when the machine has no training system. Deep Cove is delivered with no training system: no training jobs, no training data store and a read-only model. The model file is checked against its signed fingerprint every time the system starts, so any change to it is detected and recorded.

The contract says the same thing in plain words. BC's data may not be used for training, tuning, evaluation, product improvement, analytics or market research, and that clause survives the end of the agreement.

Four checks BC can run itself

  1. Read the software inventory

    Every release arrives through the Delivery Bay with a complete list of its components. BC can confirm that no training pipeline is present.

  2. Compare the fingerprint

    The model's fingerprint is written to BC's log at every start. It matches the signed release record, or the log shows that it does not.

  3. Read the crossings

    The log lists everything that crossed the wall around the Core. There is no export path out of the facility. Exports for access requests, audits and backups are BC actions, made at the on-site console, each one logged.

  4. Test it independently

    An independent penetration test before go-live examines the Core, the Gates and the update path, and the full report goes to BC.

This answers the question BC's privacy regulator already asks. In its guidance on AI scribes, BC's Office of the Information and Privacy Commissioner tells health organizations to ask whether a vendor will use data “for any secondary purposes (e.g., ... training the AI model)” and whether personal information will be “sent outside of Canada”.3 For Deep Cove, both answers are no.

  1. 3OIPC BC, “PIPA and AI scribes: best practices for healthcare organizations in BC”, oipc.bc.ca guidance document 3082.
Expert DetailSupply Chain and Model Integrity
  • Model weights are stored in a non-executable tensor format, and their hash and signature are checked at every start against a manifest signed offline under a two-person rule.
  • A software bill of materials (SBOM) is delivered with every release.
  • Each release is checked on a separate machine before it reaches the Delivery Bay: malware scanning, signature and hash checks, a component diff against the last release, and the full clinical safety suite.
  • Release media is mounted read-only through a hardware write-blocker, so the system can never write data onto it.
  • Canada's federal, provincial and territorial privacy commissioners, including BC's, ask that personal information used for training AI be “limited to what is necessary for the purpose” (Principles for Responsible, Trustworthy and Privacy-Protective Generative AI Technologies, 7 December 2023). Deep Cove uses none.

Expert DetailThe Statutes, Section by Section
  • FIPPA, RSBC 1996 c.165 (consolidation current to 10 November 2026).

    • s.30.5(2): a service provider's employee or associate who knows of an unauthorized disclosure “must immediately notify the head of the public body.”
    • s.31: information used “to make a decision that directly affects the individual” is kept “for at least one year after being used”.

6Audit Rights

Every question, lookup and answer is written to a log that BC owns. The log is hash-chained, so each entry carries the fingerprint of the one before it and any edit shows. It is encrypted, stored on BC's hardware and kept for as long as BC decides.

BC can audit everything; Deep Cove Intelligence can audit nothing on its own. Reading the log is itself logged. Logging cannot be switched off from the console; changing what is logged takes two people, is itself logged and alerts the hospital's security operations. Our engineers see the log only on site, under BC supervision.

What each log entry holds

  • Who asked, when, and from which session
  • Every order the AI placed, the gate's decision and the reason
  • The sources returned, by reference
  • The model's fingerprint and the release in use
  • The answer the clinician saw

What BC can do with it

  • Answer access requests. Export everything about a clinician or a patient by date range; the Records Librarian's pseudonym map, held in BC under two-person access, links a patient to their log entries for a request under FIPPA Part 2.
  • Scope an incident exactly. See who saw what, and when, before deciding on notification.
  • Audit us. The agreement gives BC, and the Information and Privacy Commissioner, the right to audit Deep Cove Intelligence's handling of the system.
  • Watch the only outbound line. A daily sample and a weekly report of every outbound search and every block go to the privacy officer.

Assurance is part of the delivery plan. An independent penetration test of the Core, the Gates and the update path is completed before go-live, and Deep Cove Intelligence's ISO/IEC 27001 and ISO/IEC 42001 programme is part of the delivery plan.

Expert DetailLog Design and Assurance
  • Hash-chained, tamper-evident journal; the chain head is written to write-once storage.
  • Encrypted at rest, role-restricted; logs hold personal health information and are protected as such.
  • Retention set by BC (minimum per FIPPA s.31 or PIPA s.35), followed by scheduled crypto-shredding, with a deletion record. Each retention period's entries are encrypted under their own key; destroying the key at the end of the period deletes the content, while the chain of hashes still verifies.
  • Whether intermediate model reasoning is kept is a BC setting.
  • Alarms (gate rejections, integrity checks, tamper) go one way to BC's security operations over a one-way link that carries no patient text.
  • Break-glass administration needs several named custodians, sends an alarm at once and is reviewed afterwards.
  • Anyone from Deep Cove Intelligence who works on the system passes a criminal record check and signs a confidentiality undertaking.
  • Controls are mapped to NIST SP 800-53 (AU-9 audit protection, AU-10 non-repudiation, AC-3(2) dual authorization) and to BC's Defensible Security control groups. “Mapped to” describes our design; it is not a certification.

7The clinician decides

Kit does not make clinical decisions. Licensed clinicians do.

Kit is clinical decision-support software for licensed health professionals. Every answer shows its sources, so the clinician can check the basis and decide.

Kit drafts and advises; the clinician reviews, edits and signs.

BC governs every change. A BC change board decides whether and when each update is installed, BC's security and clinical safety officers sign each release, and every release passes Kit's clinical safety suite before clinicians see it.

8Health Canada Positioning

Image and document reading is non-diagnostic. Diagnostic imaging follows Health Canada's medical-device pathway, in a later phase, when BC asks for it.

Clinical Decision Support

For licensed professionals, with the basis shown. Kit never makes the diagnosis or the triage decision itself.

Non-Diagnostic Reading

Documents, forms, letters and general photographs; no medical images.

Medical-Device Pathway

Diagnostic imaging, later, under a Health Canada licence.

Expert DetailHealth Canada's Four Criteria

Health Canada's Software as a Medical Device (SaMD): Definition and Classification sets four criteria; software that meets all four is outside device regulation:

  1. “not intended to acquire, process, or analyze a medical image or a signal from an IVDD”;
  2. “intended to display, analyze, or print medical information about a patient or other medical information”;
  3. “only intended to support a health care professional, patient or non healthcare professional caregiver in making decisions”;
  4. “not intended to replace the clinical judgement of a health care professional to make a clinical diagnosis”.

Its key test: “The intended user should have access to the basis for the software's recommendation, so the user can independently review and rely on their own judgement.” Kit's cited answers are built to meet it.

Kit stays inside these criteria because, as delivered, it does not accept medical images or signals (X-ray, CT, MRI, ultrasound, pathology slides, ECG tracings) for interpretation; it reads documents, forms and general photographs only. Kit is offered to licensed professionals as decision support: it never makes the diagnosis or the triage decision itself. It lists possibilities, red flags and next steps with their sources, and the licensed clinician decides. Dose output is a referenced calculation the clinician can check against its source. The intended-use statement is written into the agreement and shown in the interface.

Diagnostic imaging would be a Class II or higher licence under Health Canada's Pre-market guidance for machine learning-enabled medical devices (page modified 17 September 2026), which allows a predetermined change control plan for pre-authorized model updates.

9First Nations Data Governance

First Nations hold rights over data about First Nations people, and those rights come first. Before any Deep Cove site handles such data, Deep Cove Intelligence will engage the First Nations Health Authority and the communities concerned, and follow the governance they set.

The design keeps every option open. The data stays on hardware in BC facilities, under BC's keys and log, so the First Nations principles of OCAP® (ownership, control, access and possession) can be applied there, under the governance the First Nations Health Authority and communities set.

10Questions from Privacy Officers

Straight answers to the questions privacy offices, officials and security teams ask first.

Patient Data

Does patient data leave the facility?

No. Patient records never leave the facility. The only outbound crossing is a cleaned search query from the Web Librarian, and the requests for the public pages it returns, with no patient identifiers; each query is checked twice and rebuilt from a medical vocabulary before it leaves. With the Sealed Library option, the Web Librarian has no outbound line, and no search words leave the facility.

Is patient data used to train Kit?

No. Deep Cove is delivered with no training system, its model is a read-only file checked against its signed fingerprint at every start, and the agreement bars training, tuning, evaluation, product improvement, analytics and market research on BC's data. Deep Cove Intelligence never receives the data, so it has nothing to train on.

Can Deep Cove Intelligence see our data?

No. There is no remote access path. Our engineers work on site only, escorted by BC staff, and every entry and console session is logged. Deep Cove Intelligence holds no copy of patient data and no data key.

Who holds the keys?

BC does. Data keys and disk recovery keys are generated in BC's hardware security modules and held by BC; break-glass credentials are split between five named BC custodians, any three of whom are needed, in sealed envelopes in separate safes. Deep Cove Intelligence holds only the key that signs its software releases, which proves an update is genuine and opens no data.

Does Kit record the visit?

No. Kit does not capture audio. It drafts notes from the clinician's own summary or the clinic's existing transcript, and the clinician reviews and signs.

BC Law and Governance

Does BC's cross-border privacy assessment apply?

No. B.C. Reg. 294/2021 requires it only where sensitive personal information is stored outside Canada, and Deep Cove stores nothing outside Canada. The normal privacy impact assessment still applies, and we deliver a PIA Input Pack written under the headings of BC's PIA Directions, ready to copy into your template.

How long are records and logs kept?

As long as BC decides. BC sets retention at installation: at least one year where an answer is used for a decision about a person, as FIPPA s.31 requires. At the end of each period, data is securely deleted on schedule, and the deletion is logged.

How do we handle an access request or a breach?

From the log. BC can export every question, lookup and answer by person and date range for an access request. For a suspected breach, the log shows exactly who saw what, and when; Deep Cove Intelligence notifies the head of the public body immediately, as FIPPA s.30.5(2) requires.

Is Deep Cove certified?

Not by a regulator, because no Canadian privacy regulator certifies AI systems. Deep Cove is designed to align with FIPPA, the E-Health Act and the Canadian Centre for Cyber Security's guidance, and its controls are mapped to NIST SP 800-53. An independent penetration test before go-live and an ISO/IEC 27001 and ISO/IEC 42001 programme are part of the delivery plan.

The System

Which AI model runs inside?

Deep Cove does not trust the model. The model has no network, no credentials and no write path; it can only place schema-checked orders through the Gates, and separate machines check each one. The model's identity and its evaluations are provided to the buyer under NDA in due diligence.

Is Kit a medical device?

Kit is clinical decision-support software for licensed professionals, and the clinician decides. It shows the basis for every answer, and its image and document reading is non-diagnostic. Diagnostic imaging follows Health Canada's medical-device pathway in a later phase, when BC asks for it.

What happens if the internet line is cut?

Kit keeps answering. The Core never uses the internet, so only live web lookups pause. Sites with the Sealed Library see no change at all. The Core runs on hospital power, with battery backup and the hospital generator behind it.

What if Deep Cove Intelligence stops trading?

The installed system keeps running. It needs no licence server, no connection to Deep Cove Intelligence and no outside service to answer. The agreement sets the continuity terms, including a perpetual licence to the installed version and source-code escrow.
